# Fix B1, B2, B3 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the three bugs found in the 2026-10-04 repository review: the React package cannot read an API Resource response (B1), flat search columns become ambiguous once a relation sort adds a join (B2), and hiding every searchable column silently widens the search instead of narrowing it (B3).

**Architecture:** Three independent fixes, one task each, each shippable alone. B1 normalizes both response envelopes inside `useDatatable` (one place every consumer routes through). B2 qualifies flat search columns with the base table (or its alias) inside `SearchApplier`. B3 extracts the search-columns derivation from `DataTable` into a pure function that also reports "search disabled", and the toolbar disables the input in that state.

**Tech Stack:** PHP 8.3+/Laravel 12–13, Pest 4 + Testbench (SQLite in-memory); TypeScript, React, TanStack Query v5 / Table v8, Vitest + RTL.

**Spec:** `docs/superpowers/reviews/2026-10-04-repository-review.md` (sections B1, B2, B3).

### Task 2 (B2): qualify flat search columns with the base table

Confirmed reproduction: search on `['title','created_at']` + `sort_by=author.first_name` → `SQLSTATE[HY000]: ambiguous column name: created_at`. `SortApplier` adds `left join test_users as author`, while `SearchApplier` emits `"created_at" like ?` unqualified.

    /**
     * Name to qualify base-table columns with: the alias for "table as alias",
     * the table otherwise, '' when the from clause is not a plain identifier.
     * Unlike baseTableFor(), which needs the real table name to derive keys.
     */
    private function qualifierFor(Builder $builder): string
    {
        if ($builder instanceof QueryBuilder && is_string($builder->from)) {
            $parts = preg_split('/\s+as\s+/i', $builder->from, 2);

            return $parts[1] ?? $parts[0];
        }

        return $this->baseTableFor($builder);
    }
```

### Task 3 (B3): hiding every searchable column disables search instead of widening it

import type { ColumnDef, VisibilityState } from '@tanstack/react-table'

export function columnId<T>(column: ColumnDef<T, unknown>): string {
  if ('accessorKey' in column) return String(column.accessorKey)
  if (column.id) return column.id
  throw new Error('laraveldatatable: every column needs an accessorKey or an explicit id.')
}

/**
 * Columns to send as `search_columns`. When columns opt in via
 * `meta.searchable` but all of them are hidden, search is disabled: sending
 * an empty list would make the backend search its whole whitelist instead.
 */
export function resolveSearchColumns<T>(
  columns: ColumnDef<T, unknown>[],
  visibility: VisibilityState,
): { columns: string[]; disabled: boolean } {
  const declared = columns.filter((c) => c.meta?.searchable).map(columnId)
  const visible = declared.filter((id) => visibility[id] !== false)
  return { columns: visible, disabled: declared.length > 0 && visible.length === 0 }
}
```
